## 1. The project

A **personal asset CDN + gallery** built on a public GitHub repository. The goal is to make hosting and sharing images and videos friction-free:

- Drop a file into `assets/` → push → it's live at a permanent CDN URL.
- Browse / search / copy URLs from a built-in gallery served via GitHub Pages.
- No server, no database, no auth, no upload UI. Just `git push`.

**Repo:** `omarjnbz/Assets-` → https://github.com/omarjnbz/Assets-

**URLs after setup:**
- Gallery: `https://omarjnbz.github.io/Assets-/`
- CDN base: `https://cdn.jsdelivr.net/gh/omarjnbz/Assets-@main/`
- Example asset URL: `https://cdn.jsdelivr.net/gh/omarjnbz/Assets-@main/assets/images/photo.jpg`

## 2. Architecture decisions (already made — don't relitigate unless asked)

| Decision | Choice | Why |
|----------|--------|-----|
| Where assets are served from | **jsDelivr CDN** (free, global edge cache, purpose-built for hotlinking from GitHub) | Faster than raw GitHub; no rate limits for normal use; permanent URL format `cdn.jsdelivr.net/gh/owner/repo@branch/path` |
| Where the gallery is hosted | **GitHub Pages** (root of `main` branch) | Free static hosting, no separate deploy step |
| Manifest generation | **GitHub Action** on push to `assets/**` runs a Node script, commits back `manifest.json` | Keeps the gallery purely static — no backend, no fetch to GitHub API needed |
| Gallery interaction | **Browse + URL copy** (no upload UI in the gallery) | Adding files = `git push`, deliberately. Keeps the system stateless and free |
| File size constraint | Soft cap ~100 MB per file (GitHub limit), small clips only | User confirmed no large videos |
| Design direction | Dark archive/terminal aesthetic — italic serif wordmark, JetBrains Mono everywhere else, acid-lime accent (`#c8f73c`), hairline borders, no rounded corners | Single distinctive look that says "utility for builders" without generic AI gloss |

## 3. Repo layout

```
Assets-/
├── README.md                       ← user-facing setup guide
├── HANDOFF.md                      ← this file
├── index.html                      ← gallery UI (single file, vanilla JS)
├── manifest.json                   ← auto-generated by the Action
├── .gitignore
├── .github/
│   └── workflows/
│       └── build-manifest.yml      ← rebuilds manifest on push to assets/
├── scripts/
│   └── build-manifest.js           ← walks assets/, writes manifest.json
└── assets/
    ├── images/.gitkeep
    ├── videos/.gitkeep
    └── other/.gitkeep
```

### Key files at a glance

- **`scripts/build-manifest.js`** — Walks `assets/` recursively. For each file emits `{name, path, type, ext, size, sizeHuman, modified, cdnUrl, rawUrl}`. Detects repo info from `GITHUB_REPOSITORY` env (Actions) or git remote (local). URL-encodes paths so filenames with spaces/parens work. Type detection by extension (`IMAGE_EXTS`, `VIDEO_EXTS`, `AUDIO_EXTS` sets — extend these to add new types).

- **`.github/workflows/build-manifest.yml`** — Triggers on push to `main` when `assets/**`, the build script, or the workflow itself changes. Also `workflow_dispatch` for manual runs. Permission: `contents: write`. Commits `manifest.json` back with `[skip ci]` to avoid loops.

- **`index.html`** — Single-file gallery. Loads `manifest.json`, renders grid with thumbnails (lazy-loaded for images, video element with `preload=metadata` for videos, icon for audio/other). Modal on click with four URL modes: Direct CDN / Raw GitHub / Markdown / HTML embed. Keyboard: `/` focuses search, `Escape` closes modal/clears search. CSS variables at the top of `<style>` control the entire palette.

## 6. Open items / candidate next features

Things explicitly **not built** but reasonable to add:

- **Custom domain** for the gallery (e.g. `cdn.omarjnbz.com`) — supported by GitHub Pages out of the box, add `CNAME` file + DNS record
- **Versioned URLs** — tag releases (`v1`, `v2`) and let the gallery surface `cdn.jsdelivr.net/gh/.../Assets-@v1/...` for immutable links
- **Bulk URL copy** — checkbox-select multiple assets, copy as a JSON array or newline-separated list
- **Per-file metadata sidecar** — `.alt.txt` next to images for alt text, surfaced in the gallery and HTML snippet
- **Thumbnail generation** — pre-generate 400px webp thumbnails so the grid loads instantly even with many large originals (would need a second Action step using `sharp` or `imagemagick`)
- **Tag/folder filter** — the manifest already records `folder`; UI doesn't surface it as a filter yet
- **Drag-and-drop staging UI** — a separate static page that lets you drag files in to download them as a zip ready for `git add` (would NOT upload; just helps prep)
- **Stats** — total bytes by type, most-recent additions, etc.
- **Image-dimensions detection** — currently no width/height; could add via a tiny image-size dependency in the build script

Anything in this list is fair game; none of it is blocking the core flow.

## 7. Style guide for the gallery (if iterating on UI)

- **Palette** is in CSS variables at the top of `index.html`. Don't add new colors without retiring one — the palette is intentionally minimal.
- **Accent** (`--accent: #c8f73c`) is the only saturated color. Use sparingly: focus states, hover highlights, active filters, the copy-success state. If everything is accented, nothing is.
- **Typography**: two fonts only. Instrument Serif italic for **one** thing (the wordmark). JetBrains Mono for everything else. Resist adding sans-serif.
- **No rounded corners.** Sharp edges everywhere — it's part of the utility-tool feel.
- **Hairline borders** (`1px solid var(--border)`) over fills wherever possible.
- **Lowercase by default** for UI labels — uppercase only for `text-transform: uppercase; letter-spacing: 0.1em+` tags (the "stat" and "kbd" treatment).
